# DeskHalloumi 0.4.0

DeskHalloumi 0.4.0 completes the shared provider lifecycle migration introduced
in 0.3.0 and hardened through 0.3.3. It preserves the existing CLI,
configuration, IPC, path, application-ID, service, generated-i3, and `unilii-*`
compatibility contracts.

## Highlights

- Clock, battery, network, audio, system, and optional Tmux providers now use one
  shared lifecycle path for bounded refresh admission, timeout, cancellation,
  refresh and instance generations, last-known-good retention, disabled/error
  states, bounded shutdown, and metrics.
- Provider-specific ownership for the built-in audio, network, and system
  collectors moved out of the Iced composition root into `provider_runtime.rs`.
- Every production provider has an executable hardware- or service-free backend
  for ordinary tests. Battery-less hosts and unavailable tmux servers publish an
  explicit disabled state instead of failing startup.
- The process-wide provider status registry rejects stale replaced instances and
  exposes health, instance generation, refresh generation, age, refresh policy,
  and bounded errors over the existing action bus.
- `deskhalloumi provider-status [--json]` provides live provider diagnostics, and
  the panel displays a compact worst-provider health badge.
- Runtime metrics now include provider refresh failures/timeouts and provider
  shutdown failures/timeouts.
- Repeated replacement coverage exercises 128 provider generations and verifies
  that stale instances cannot overwrite the active status and refresh permits do
  not leak.
- The release workflow adds a native `ubuntu-24.04-arm` AArch64 build,
  installation, command-smoke, checksum, and removal lane. Publication is
  deferred until both x86-64 and native AArch64 archives pass.
- ADR 0001 records the decision not to publish a musl artifact for 0.4.x. The
  desktop graphics, DBus, input, font, and session-service boundary remains
  explicit rather than being hidden behind a different libc target.

## Operator notes

Use the live provider report with:

```sh
deskhalloumi provider-status
deskhalloumi provider-status --json
```

The command requires a running DeskHalloumi bar and uses the same bounded local
action bus as `runtime-metrics`. Errors are bounded and do not include captured
provider command output.

No configuration migration is required. Existing provider refresh intervals and
public command names remain compatible.

## Architecture and release scope

The native AArch64 lane is part of the tag-triggered GitHub workflow and cannot
be executed on the local x86-64 release host. A local source tag or x86-64
archive does not imply that the native lane passed or that a remote release was
published. The workflow publishes both GNU/Linux architectures only after the
native lane succeeds.

No musl artifact is published for 0.4.x. See
[`docs/adr/0001-no-musl-release-artifact-for-0.4.md`](../adr/0001-no-musl-release-artifact-for-0.4.md).
