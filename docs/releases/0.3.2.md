# DeskHalloumi 0.3.2

Release date: 2026-07-27

DeskHalloumi 0.3.2 supersedes the untagged 0.3.1 candidate. It is a
production-hardening patch for the hotkey daemon, Iced bar runtime, local IPC,
and i3/X11 integration. It preserves the command, configuration-path,
action-bus, application-ID, and `unilii-*` compatibility contracts published in
0.3.0.

## Highlights

- Hotkey execution uses a 64-entry admission queue, four concurrent actions,
  supervised Tokio subprocesses, 30-second timeouts, process-group cleanup, and
  bounded retained output.
- Action-bus and hotkey-control requests and responses enforce their 64 KiB
  limits while reading and writing. Read/write phases are timeout-bounded, and
  the bar admits at most 32 simultaneous action-bus clients.
- The selective X11 event thread publishes through a 256-entry bounded queue and
  applies backpressure without dropping press/release ordering.
- Runtime metrics expose active and queued actions plus completed, failed,
  cancelled, timed-out, and rejected totals. Guard-owned gauges recover
  correctly when a future or queue is cancelled.
- Live bar reloads are generation-checked. A slow result from an older request
  cannot replace a newer configuration.
- Strict reload validation retains last-known-good state. Runtime-safe menu
  settings apply immediately; panel geometry, module topology, and embedded
  hotkey changes remain explicitly restart-required.
- Bar actions support reload, visibility toggling, focus, restoring all hidden
  modules, clearing focus, and orderly quit. Both colon forms and the documented
  space-separated `toggle-module <name>` and `focus-module <name>` aliases work.
- Generated i3 includes use unique temporary files, preserve permissions, sync
  file and parent-directory state, and roll back when live i3 reload rejects a
  candidate.
- Hotkey source watching detects same-length atomic replacements through device,
  inode, modification-time, change-time, and length fingerprints.
- Tray animation ticks exist only while animation is moving, and module render
  paths no longer emit per-frame information logs.
- `scripts/check_build_space.py` detects insufficient release build space before
  LLVM fails deep into a build. It is diagnostic-only and never deletes files.

## Bar action reference

```text
reload-config
config:reload
bar:reload

toggle-module:<name>
toggle-module <name>
bar:toggle:<name>

focus-module:<name>
focus-module <name>
bar:focus:<name>

show-all-modules
modules:show-all
bar:show-all

clear-module-focus
modules:clear-focus
bar:clear-focus

quit
bar:quit
```

`toggle-module` changes presentation visibility without terminating its provider.
`focus-module` reveals and prioritizes the selected module. The recovery actions
restore normal presentation if a sequence of hotkeys leaves modules hidden or
focused.

## Operational notes

The recommended production topology remains:

```sh
deskhalloumi run --no-hotkeyd
deskhalloumi-hotkeyd --config ~/.config/deskhalloumi/hotkeys.toml --watch
```

For ordinary press/release shortcuts on i3/X11, generated i3 bindings remain the
preferred deployment. The selective X11 backend remains appropriate for hold,
modifier-release, repeat, cooldown, priority, and consume semantics.

The action and control protocols remain private, user-scoped, versioned,
line-delimited JSON protocols. Oversized, unterminated, invalid UTF-8, stale,
and unsupported messages fail locally without disabling unrelated bindings.
