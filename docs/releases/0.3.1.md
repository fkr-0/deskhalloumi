# DeskHalloumi 0.3.1

Release date: 2026-07-26

DeskHalloumi 0.3.1 is a production-hardening release for the hotkey daemon, the
Iced bar runtime, and i3/X11 integration. It preserves the existing command,
configuration-path, action-bus, and compatibility-launcher contracts.

## Highlights

- Bounded hotkey execution with four concurrent actions, a 64-entry admission
  queue, supervised Tokio subprocesses, 30-second timeouts, process-group
  cleanup, and bounded captured output.
- Bounded bar, tray, and embedded action channels with explicit overload
  responses and runtime counters instead of unbounded memory growth.
- Concurrent control-socket clients with serialized supervisor mutations, so a
  stalled client cannot delay signals, reload observation, or another request.
- Working bar actions for `reload-config`, `toggle-module:<name>`, and
  `focus-module:<name>` with concise visible status feedback.
- Strict live configuration validation that retains the last-known-good state;
  menu settings apply immediately while panel geometry, module topology, and
  embedded-hotkey changes are reported as restart-required.
- Tray animation ticks are subscribed only while animation is moving, and
  module rendering no longer emits per-frame info logs.
- Transactional i3 include installation: when `i3-msg reload` rejects a
  candidate, the previous include is restored and reloaded once.
- Hotkey status now reports action rejection and dropped-update counters.

## Operational notes

The recommended production topology remains:

```sh
deskhalloumi run --no-hotkeyd
deskhalloumi-hotkeyd --config ~/.config/deskhalloumi/hotkeys.toml --watch
```

For ordinary press/release shortcuts on i3/X11, continue to prefer generated i3
bindings. The selective X11 backend remains appropriate for hold,
modifier-release, repeat, cooldown, and priority semantics.

Live bar reload deliberately applies only runtime-safe menu configuration.
Changes to panel geometry, loaded modules, or embedded hotkeys require a bar
restart and are listed in the UI status message.

This patch release completes and hardens behavior already advertised by the
0.3 runtime and action contracts. The planned 0.4.0 provider-hardening and
target-expansion milestone remains unchanged.
